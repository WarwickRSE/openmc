# Description

Firstly, we need to advance the events in terms of a transport distance, not the full distance to the next collision. We do this in particle.cpp by adding to extra steps in the calculation of the distance. Specifically:

- Keep the limit from next material boundary
- Keep the limit from next collision
- Keep the large limits (although these are superseded)
- Limit the maximum energy loss in a single step
- Limit the maximum distance (to resolve the small-angle)
- Limit the minimum distance to avoid collapse

Now we need to apply the path-length integrated parts, i.e. the Spherical brownian motion, the energy loss and the energy straggling. We handle these inside event_advance, which is the part responsible for moving the particle in space etc. 

Lastly, we apply the true collisions. However, because of how we altered the distance, we do not do this every time we hit the collide routine like the existing code. We still enter this process so that we get the post-event effects (mostly energy-dependent killing) after our condensed history step. Now though, we test the collision_distance against the transport_distance actually travelled. 

A few things then need patching up - we potentially change the direction in both 2 and 3, so in the case where we do a collision we have to make sure the polar angle is updated correctly. This needs a bit more checking. I _believe_ p.mu() ought to contain the final angle (i.e. the net from both steps in our code, which is unlike the existing code where only one event occurs per step)

Particle killing is done already as noted above - we just need to set the correct energy for this. The default is 500keV and there is a setting as shown in the example python file to adjust this:
``` python
settings.cutoff = {'energy_proton': 2.0e5} #Cutoff energy in eV
```
The scoring is using the built-in ‘heating’ output, which is a tracklength deposition of energy loss. It looks like it handles crossing multiple scoring grids already, but that would need some additional checking. 

## Input

There are some settings to control things like the energy at which the Protons are killed, and the maximum energy loss in one step.
These are done like so:

- Proton minimum energy - see above
- Proton maximum energy loss and minimum and maximum path step:

  ```python
  settings.proton_settings = {
      'max_step_len': 0.2,
      'min_step_len': 0.05,
      'max_energy_loss': 1e6,
  }
  ```


The physical geometry is a CSG system like Geant4. This can be set-up in many ways, and I have not looked into this beyond the basics.

```python
water.mean_excitation_energy = openmc.proton_data.mean_excitation_energy("water", proton_path + "mean_excitation_energies.txt") #eV
```

## Note on implementation

The code is built around the idea that individual nuclides ‘know’ their individual contributions to an effect. Then the material ‘knows’ the composition and evaluates the sums over nuclides. Finally, the particle ‘knows’ its position and energy so can invoke the various effects as needed.
